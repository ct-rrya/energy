## High-level view

The panel implements the exact design tokens specified: `--landing-green` (#19d46a), `--landing-surface` (white/#111b30), `--landing-ink`, `--landing-line`, etc., with 28px panel radius, 22px bubble radius (8px on speaker corner), 999px pills, and `cubic-bezier(0.65, 0, 0.15, 1)` easing. Typography is Bricolage Grotesque at the specified weights (400, 600, 800) with message text 15-16px, timestamps 12px, header title 17px weight 800. Icons are Lucide-only: `sprout`, `x`, `rotate-ccw`, `send-horizontal`, `message-square`, all 20px stroke 2. Mobile breakpoint at 560px switches to a 92dvh bottom sheet with safe-area-inset-bottom padding.

The API contract is correct: `POST /chat` with `{message, sessionId?}` expects `{response, sessionId, suggestions?}`. SessionId is stored in sessionStorage with a per-tab unique key (`ecostep_chat_session_id_${TAB_ID}`) generated via `crypto.randomUUID()`, preventing cross-tab collision. Messages are NOT persisted—only the sessionId survives page navigation.

Bot messages are parsed with `marked.parse()` and sanitized with `DOMPurify.sanitize()` before rendering via `dangerouslySetInnerHTML`. A DOMPurify hook adds `target="_blank" rel="noopener noreferrer"` to all links. The allowed tag set is `['p', 'br', 'strong', 'em', 'ul', 'ol', 'li', 'code', 'pre', 'a']` with attributes `['href', 'target', 'rel']`. User messages are plain text.

The four suggestion chips ("How does a footstep make power?", "What's the current energy status?", "What does the ESP32 do?", "How do I read the dashboard?") appear when `messages.length === 1` and disappear after the first user message. "New chat" restores them. The input is an auto-growing textarea (1-4 rows, max 96px) with Enter to send, Shift+Enter for newlines, 500-char limit, counter appearing at 400+. Send button is a green pill with `send-horizontal` icon, disabled when empty or loading.

The panel is `role="dialog"` with `aria-label="EcoChat"`, the message list is `role="log"` with `aria-live="polite"`, and the typing indicator has visually-hidden "EcoStep is typing" text. All icon-only buttons have `aria-label`. Focus trap is implemented with `focus-trap-react`. Escape closes the panel and returns focus to the launcher.

Error handling displays friendly messages ("I couldn't reach EcoStep right now. Check your connection and try again.") with a Retry button. Client-side rate limiting enforces 1.5 seconds between messages. HTTP 429 shows "Too many messages, try again in a moment." No raw error text or stack traces appear.

## API contract and session management

SessionId is stored in sessionStorage under a tab-unique key: `const TAB_ID = crypto.randomUUID(); const SESSION_ID_KEY = \`ecostep_chat_session_id_\${TAB_ID}\`;`. The UUID is generated once at module load, so each tab gets its own storage key, preventing cross-tab collision.

Clearing the chat resets to `[INITIAL_GREETING]` but does not clear the sessionId, so backend conversation context persists across "New chat" clicks.

## Markdown sanitization

Bot messages pass through `marked.parse(text, {async: false})` then `DOMPurify.sanitize(rawHtml, {ALLOWED_TAGS: ['p', 'br', 'strong', 'em', 'ul', 'ol', 'li', 'code', 'pre', 'a'], ALLOWED_ATTR: ['href', 'target', 'rel']})`. A DOMPurify hook adds `target="_blank" rel="noopener noreferrer"` to all links. The sanitized HTML is rendered via `dangerouslySetInnerHTML` in `MessageBubble.tsx`—the only occurrence in the chat feature.

## Suggestion chips and empty state

The four chips are hardcoded in `SuggestionChips.tsx`:
1. "How does a footstep make power?"
2. "What's the current energy status?"
3. "What does the ESP32 do?"
4. "How do I read the dashboard?"

They are displayed only when `messages.length === 1`. After the first user message, the chips disappear. "New chat" restores them.

## Input behavior

The textarea auto-grows to a maximum of 96px (approximately 4 rows). Enter sends, Shift+Enter adds a newline. 500-character limit enforced; counter appears at 400+, positioned `position: absolute; bottom: 12px; right: 20px;` with `pointer-events: none`.

The Send button is disabled when `value.trim().length === 0 || disabled`. Disabled opacity is 0.45. On press, the button scales to 0.95.

## Error handling

Client-side rate limiting enforces 1.5 seconds between messages. Error messages are friendly: "Too many messages, try again in a moment" for HTTP 429, "I couldn't reach EcoStep right now. Check your connection and try again" for network failures. No raw error text or stack traces.

The error bubble sits between the message list and input with 8px margin-top, providing visual separation from the input's focus shadow.

## Accessibility

Focus trap implemented with `focus-trap-react`. Escape closes the panel and restores focus to the launcher. The panel is `role="dialog" aria-label="EcoChat"`, the message list is `role="log" aria-live="polite"`, and the typing indicator has visually-hidden "EcoStep is typing" text.
