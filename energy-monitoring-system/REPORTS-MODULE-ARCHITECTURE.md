### Architectural Principles to Follow

✅ **Service-Oriented**: Use existing services, never direct DB access  
✅ **Single Responsibility**: Reports module only generates reports  
✅ **DRY**: Reuse calculations from Analytics, never duplicate  
✅ **Modular**: Controller → Service → PDF/Excel generators  
✅ **Secure**: JWT protected, access control, file validation

## 2. INTEGRATION STRATEGY

### Service Dependencies

```typescript
// Reports Service Dependencies
@Injectable()
export class ReportsService {
  constructor(
    private analyticsService: AnalyticsService,  // ← Main data source
    private energyService: EnergyService,        // ← Backup/raw data

    // PDF/Excel generators injected

```

### Data Flow

```
User Request (JWT)
    ↓
Reports Controller
    ↓
Reports Service
    ├─→ AnalyticsService.getDailySummary()
    ├─→ AnalyticsService.getWeeklySummary()
    ├─→ AnalyticsService.getMonthlySummary()
    ├─→ AnalyticsService.calculateEnvironmentalImpact()
    ├─→ AnalyticsService.calculateCostSavings()
    ├─→ AnalyticsService.getPeakGeneration()
    ├─→ UsersService.findById() (for "Generated By")
    ↓
Format Data → Generate PDF/Excel
    ↓
Save to File System + MongoDB metadata
    ↓
Return File URL/Stream to User
```

### Integration Benefits

1. **No Code Duplication**: All calculations already in AnalyticsService
2. **Consistency**: Same formulas used everywhere
3. **Maintainability**: Fix calculation once, works everywhere
4. **Testability**: Mock services easily
5. **Performance**: Analytics service already optimized

## 3. REPORT GENERATION WORKFLOW

### Workflow Diagram

```
┌─────────────────────────────────────────────────┐
│         Report Generation Workflow              │
└─────────────────────────────────────────────────┘

1. User Requests Report
   POST /api/reports/generate
   {
     "type": "monthly",
     "format": "pdf",
     "year": 2026,
     "month": 7
   }
   
2. Validate Request
   • Check auth (JWT)
   • Validate parameters
   • Check rate limiting
   
3. Check Cache (Optional)
   • Same report generated recently?
   • Return cached if < 1 hour old
   
4. Fetch Data from Services
   • AnalyticsService.getMonthlySummary()
   • AnalyticsService.calculateEnvironmentalImpact()
   • AnalyticsService.calculateCostSavings()
   • UsersService.findById() (current user)
   
5. Generate Report File
   • PDF: Use PDFKit or Puppeteer
   • Excel: Use ExcelJS
   • Apply template/styling
   
6. Save Report
   • File: ./uploads/reports/[filename]
   • Database: Metadata only
   
7. Return Response
   {
     "success": true,
     "data": {
       "id": "report-123",
       "fileUrl": "/api/reports/download/report-123",
       "fileName": "monthly-report-2026-07.pdf",
       "size": 245678
     }
   }
   
8. Cleanup (Background Job)
   • Delete reports older than 30 days
   • Clean up orphaned files
```

### Async vs Sync Generation

**Recommendation**: **Synchronous** (for simplicity)

**Rationale**:
- Reports generate in < 5 seconds (small dataset)
- Simple undergraduate implementation
- No job queue needed
- Immediate download

**Future Enhancement**: Add async for large reports
- Use Bull queue
- Email when ready
- Track progress

## 4. LIBRARY RECOMMENDATIONS

### PDF Generation Libraries

#### Option 1: **PDFKit** ⭐ RECOMMENDED

**Pros**:
- ✅ Pure JavaScript (no external dependencies)
- ✅ Small bundle size (~200KB)
- ✅ Programmatic control (charts, tables, formatting)
- ✅ Streams support (memory efficient)
- ✅ Well-documented
- ✅ Active maintenance
- ✅ No browser needed

**Cons**:
- ⚠️ Manual positioning (more code)
- ⚠️ No HTML→PDF conversion
- ⚠️ Charts need manual drawing or library

**Best For**: Production-grade, server-side PDF generation

```typescript
import PDFDocument from 'pdfkit';

const doc = new PDFDocument();
doc.fontSize(20).text('Energy Report', 100, 100);
doc.pipe(fs.createWriteStream('report.pdf'));
doc.end();
```

---

#### Option 2: **Puppeteer**

**Pros**:
- ✅ HTML→PDF conversion (easy templating)
- ✅ Perfect rendering (uses Chrome)
- ✅ Charts from Chart.js/D3.js work
- ✅ CSS styling support

**Cons**:
- ❌ Large bundle (~300MB with Chrome)
- ❌ Memory intensive
- ❌ Slower generation (2-5 seconds)
- ❌ Requires browser binaries
- ❌ Complex deployment

**Best For**: HTML-heavy reports, complex layouts

```typescript
import puppeteer from 'puppeteer';

const browser = await puppeteer.launch();
const page = await browser.newPage();
await page.setContent(htmlContent);
await page.pdf({ path: 'report.pdf' });
```

---

#### Option 3: **jsPDF**

**Pros**:
- ✅ Lightweight
- ✅ Client + server support
- ✅ Simple API

**Cons**:
- ⚠️ Limited features
- ⚠️ Poor table support
- ⚠️ Less professional output

**Best For**: Simple receipts, invoices

---

### Excel Generation Libraries

#### Option 1: **ExcelJS** ⭐ RECOMMENDED

**Pros**:
- ✅ Full Excel feature support (formulas, charts, styling)
- ✅ Read and write Excel files
- ✅ Well-documented
- ✅ Active development
- ✅ TypeScript support
- ✅ Stream support (memory efficient)

**Cons**:
- ⚠️ Larger bundle (~500KB)
- ⚠️ More complex API

**Best For**: Professional Excel reports

```typescript
import ExcelJS from 'exceljs';

const workbook = new ExcelJS.Workbook();
const worksheet = workbook.addWorksheet('Energy Report');
worksheet.addRow(['Date', 'Energy (kWh)', 'Cost ($)']);
await workbook.xlsx.writeFile('report.xlsx');
```

---

#### Option 2: **xlsx** (SheetJS)

**Pros**:
- ✅ Lightweight
- ✅ Fast
- ✅ Simple API

**Cons**:
- ⚠️ Limited styling
- ⚠️ Commercial license for some features
- ⚠️ Less professional output

**Best For**: Simple data dumps

---

### **FINAL RECOMMENDATION**

| Feature | Library | Reason |
|---------|---------|--------|
| **PDF** | **PDFKit** | Production-ready, lightweight, no external deps |
| **Excel** | **ExcelJS** | Full features, professional output |

**Total Bundle Impact**: ~700KB (acceptable)

**Trade-offs Accepted**:
- More code for PDF (vs Puppeteer's HTML)
- Slightly larger Excel library (vs xlsx)
- **Benefits**: Professional output, maintainable, deployable

## 5. DATABASE SCHEMA DESIGN

### Report Metadata Schema

**Purpose**: Track generated reports (NOT store file content)

```typescript
@Schema({ timestamps: true })
export class Report {
  @Prop({ required: true, enum: ['daily', 'weekly', 'monthly', 'custom'] })
  type: string;  // Report type
  
  @Prop({ required: true, enum: ['pdf', 'excel'] })
  format: string;  // File format
  
  @Prop({ required: true })
  fileName: string;  // Unique file name
  
  @Prop({ required: true })
  filePath: string;  // Relative path: uploads/reports/...
  
  @Prop({ required: true })
  fileSize: number;  // Bytes
  
  @Prop({ required: true, type: Types.ObjectId, ref: 'User' })
  generatedBy: Types.ObjectId;  // Who generated it
  
  @Prop({ required: true })
  startDate: string;  // YYYY-MM-DD
  
  @Prop({ required: true })
  endDate: string;  // YYYY-MM-DD
  
  @Prop({ type: Object })
  parameters: any;  // Additional params (sensor filter, etc.)
  
  @Prop({ type: Object })
  summary: {
    totalEnergyKWh: number;
    avgPowerW: number;
    co2AvoidedKg: number;
    costSavings: number;
  };
  
  @Prop({ default: 0 })
  downloadCount: number;  // Track downloads
  
  @Prop()
  expiresAt: Date;  // Auto-delete after 30 days
  
  // Timestamps: createdAt, updatedAt (automatic)
}
```

### Indexes

```typescript
// Compound index for user's reports
ReportSchema.index({ generatedBy: 1, createdAt: -1 });

// TTL index for auto-deletion
ReportSchema.index({ expiresAt: 1 }, { expireAfterSeconds: 0 });

// Type and format index
ReportSchema.index({ type: 1, format: 1 });
```

### Storage Strategy

**Files**: File system (`./uploads/reports/`)  
**Metadata**: MongoDB  
**Retention**: 30 days (auto-delete via TTL)  

**Why not store files in MongoDB?**
- ❌ MongoDB GridFS adds complexity
- ❌ Large binary blobs slow queries
- ✅ File system is simple and fast
- ✅ Easy to backup/restore
- ✅ Can serve via Nginx in production

## 7. FILE NAMING CONVENTION

### Pattern

```
{type}-report-{period}-{timestamp}.{ext}
```

### Examples

```
daily-report-2026-07-18-1721300400000.pdf
weekly-report-2026-W29-1721300400000.xlsx
monthly-report-2026-07-1721300400000.pdf
custom-report-2026-07-01-to-2026-07-15-1721300400000.pdf
```

### Components

| Component | Description | Example |
|-----------|-------------|---------|
| `{type}` | Report type | `daily`, `weekly`, `monthly`, `custom` |
| `{period}` | Time period | `2026-07-18`, `2026-W29`, `2026-07` |
| `{timestamp}` | Unix timestamp | `1721300400000` |
| `{ext}` | File extension | `pdf`, `xlsx` |

### Benefits

✅ Sortable by name  
✅ Unique (timestamp ensures no conflicts)  
✅ Human-readable  
✅ No special characters (filesystem safe)

## 8. SECURITY AND ACCESS CONTROL

### Authentication
```typescript
@UseGuards(JwtAuthGuard)  // All endpoints protected
```

### Authorization Rules

1. **Generate Report**: Any authenticated user ✅
2. **List Reports**: Only user's own reports ✅
3. **Download Report**: Only if user generated it ✅
4. **Delete Report**: Only if user generated it ✅

### Security Measures

```typescript
// 1. Validate file access
async download(id: string, userId: string) {
  const report = await this.findById(id);
  
  // Check ownership
  if (report.generatedBy.toString() !== userId) {
    throw new ForbiddenException('Access denied');
  }
  
  // Validate file exists
  if (!fs.existsSync(report.filePath)) {
    throw new NotFoundException('File not found');
  }
  
  // Validate file is within uploads directory
  const realPath = fs.realpathSync(report.filePath);
  if (!realPath.startsWith(UPLOADS_DIR)) {
    throw new ForbiddenException('Invalid file path');
  }
  
  return fs.createReadStream(report.filePath);
}
```

### Rate Limiting (Future)

```typescript
// Prevent abuse
@Throttle(5, 60)  // 5 reports per minute
async generate() {}
```

### File Validation

- ✅ Check file size (max 10MB)
- ✅ Validate file extension
- ✅ Sanitize filenames
- ✅ Store in isolated directory
- ✅ No executable permissions
